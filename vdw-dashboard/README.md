# VDW Dashboard

React + TypeScript 工作空间操作台。前端构建产物存放于 `vdw/dashboard-assets/`，随源码纳入版本管理，并在所有构建（包括 debug）中嵌入 Rust CLI。

## 用户使用

安装正式 VDW 二进制后执行 `vdw dashboard`。默认只监听 `127.0.0.1`、选择空闲端口并打开系统默认浏览器。不需要 Node、npm、源码目录或联网下载页面资源。

```sh
vdw dashboard --no-open
vdw dashboard --port 18080
```

访问命令打印的完整地址。会话密钥在 URL fragment 中，页面读入 sessionStorage 后移除，不通过 URL 查询参数或 Referer 发送。重复运行会复用相同版本实例；前台服务用 Ctrl+C 停止。远端仓库检测需要既有 Git 凭据及网络。

## 开发与交付

```sh
make dashboard-build          # 仓库根目录；仅开发者/CI 需要 Node >=20.19 + npm
make dashboard-verify         # Python 标准库校验，不需要 Node
cd vdw && cargo build --release --locked
python3 ../scripts/smoke_dashboard.py --binary target/release/vdw
```

Cargo 的 build.rs 检查资源哈希，并在完整源码 checkout 中检查 React 源码哈希。缺失或陈旧资源会阻止构建。源码发行包包含已构建资源，因此 Cargo 构建本身不执行 npm、不下载前端资源。更新前端后必须运行 `make dashboard-build`，同时提交源码、锁文件、manifest 和静态产物。

CLI 与 HTTP 共享生命周期 Engine、Git/拓扑查询和基础配置服务。HTTP 不调用另一个 VDW CLI 子进程，也不改变进程工作目录。纯状态刷新不 touch 工作空间、不恢复后台任务、不 fetch。实际 Git 检测出错单独展示，不推断为干净。“无未提交变更”只描述 Git 文件状态；卡片与详情另行展示归档结构限制。子模块检查与生命周期预检共用只读逻辑：仅对缺少 `.gitmodules` 映射、目录为空或不存在、且工作树/共享 Git 目录没有留存子模块数据或初始化配置的孤立指针允许归档。卡片、详情、计划和操作记录展示独立归档提示，提示随快照保存，恢复仍保留原指针与未初始化状态，不阻止自动归档。存在映射、实际内容（包括隐藏和忽略文件）、已初始化仓库、留存 Git 数据、符号链接或无法确认的状态仍阻止归档；预览后和移除每个工作树前重新检查。检查不初始化子模块、不修改索引，其他脏工作区、保护、租约规则继续生效。归档计划没有可执行项时禁用确认，预检失败不显示为普通跳过；操作记录的全部失败也明确显示为失败。

卡片、统计与分类统一显示“活跃 / 将归档 / 已归档”。预计归档日期取最近活动与源码修改时间较新者，结合生效闲置天数、候选记录及宽限期计算，归档前 7 天进入预警；自动归档关闭、受保护、仍在使用、存在变更或检测异常时不标为“将归档”。预估不会创建候选或执行归档，真正执行仍由生命周期预检决定。

“最近修改日期”读取源码和工作空间文件的实际修改时间，忽略 Git/VDW 运行文件、被 Git 忽略的仓库文件和常见构建目录；打开编辑器不更新时间。新归档保留该日期，缺少该字段的旧归档显示“暂无记录”。默认按最近修改排序。

归档、恢复、删除和策略变更先生成持久化计划，确认后由同一个 Engine 执行。重复提交去重，操作记录由 VDW 持久化；关闭页面不取消后台执行。自动归档单独启停确认。Store 目录、固定保护参数和未实现的云能力只读。

操作记录中的“撤销此操作”先预览反向动作，再二次确认。可撤销成功的归档、恢复、删除，以及保留完整变更前快照的配置更新；撤销保留独立记录，重复提交去重。归档撤销会恢复原空间，恢复撤销会重新归档未变化的空间，删除撤销会定位系统回收站中的原目录并恢复原登记。原路径占用、后续生命周期操作、文件/提交或配置已变化时拒绝覆盖；缺少安全快照的旧记录会显示不可撤销原因。撤销已部分执行或中断时保留结果供检查，不能盲目重试。删除记录在显示撤销入口前会检查原路径和回收凭据；macOS 旧记录先检查回收站中的确切同名路径并校验目录身份，再尝试枚举匹配，避免列表读取受限时误判。找不到、身份不符或访问受限会展示原因；预览期间发生变化导致失败时，错误持续显示在对应操作记录中。

归档、删除、恢复、撤销及配置操作结束后，主动重新加载工作空间、统计、配置和操作记录，与“自动刷新”开关无关。页面同时跟踪各个待完成任务，切换页面或提交后续操作不丢失前一任务的刷新。

“检查远端”只检查所选工作空间，每张卡片独立显示检查进度并防止重复点击，不占用归档、恢复、删除及其他卡片的操作状态。远端检测有缓存、并发和超时限制。Git 返回的权限、网络和不存在错误分别展示；无法证明删除时显示“不存在或无权限”，不会把私有仓库 404 标为已删除。只读依赖和归档仓库分别使用锁文件/归档清单展示版本。

“检查远端”分别返回仓库可访问性和开发分支是否存在，只在成功读取仓库引用后才判断分支缺失；手动检查绕过缓存。远端地址可跳转到开发分支，分支缺失时退回仓库主页，并标红“远端分支已删除”。认证或网络失败时保留分支状态未知。

打开工作空间后会检查本地及远端异常。Qoder IDE 使用官方 chat deeplink，需在 Qoder 确认预填内容；Codex 桌面端使用 `codex://new` 的工作目录和 prompt 预填草稿，不自动提交。URL 启动没有对话框送达回执，因此异常说明同时备份到系统剪贴板；不支持协议或启动失败时使用剪贴板，复制失败则提供可手动复制的说明。正常未提交变更不作为异常触发交接。

Qoder 协议参考：[官方 Deeplinks 文档](https://docs.qoder.com/user-guide/deeplink)。Codex 适配按已验证的桌面 URL 路由实现，旧版客户端无法识别时仍可使用剪贴板备份。该功能不运行修复命令，不自动创建提交、删除文件或改变分支。

本地 API 校验 Host、Origin 与随机会话令牌。编辑器使用 argv 数组启动，不经过 shell；自定义可执行文件必须为绝对路径。编辑器启动结果为“已发送打开请求”，不推断 IDE 已加载项目。

卡片底部的“删除”先展示名称、完整目录及影响范围，二次点击“移到回收站”才执行整目录回收。包含未提交、未跟踪和忽略文件，不清理工作树内容；共享 Store、远端及历史归档保留。系统回收站不可用时报告失败，不降级为永久删除。运行中、受保护或有有效编辑器租约的工作空间不可删除；确认前会重新验证登记和目录身份。

删除成功的登记标记为 `trashed` 并从看板隐藏，操作记录仍可查询。共享 Git 工作树的管理目录加保留锁，Store 引用另行留存以避免回收站期间被 GC 清理。macOS 通过 Foundation API 回收，不需要 Finder 自动化权限；新删除记录保存系统回收凭据，可直接在操作记录中撤销删除；旧记录缺少凭据或系统回收站已清空时需手动检查。部分系统不提供“放回原处”，也可从回收站拖出目录。从回收站放回原路径后，对原活跃空间执行 `vdw workspace touch <workspace_id>`，或正常执行 VDW 操作，可恢复原登记；纯看板刷新保持只读。删除后也可以在原路径创建新的同名空间，回收保留记录独立存续。

回收边界的单测使用临时目录模拟系统移动/失败；真实系统回收验证需显式启用 `python3 scripts/smoke_dashboard.py --binary vdw/target/release/vdw --test-system-trash`，只将一个名称唯一的临时测试工作空间移入系统回收站，并验证撤销找回全部文件和原登记。
